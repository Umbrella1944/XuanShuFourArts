## 玩家使用

在游戏 MOD 管理中打开玄枢四诀的详细设置。五个独立滑块范围均为 10%～300%，步长 10%，默认 100% 保持原数值。保存后完整退出并重启游戏，功法及套装说明显示本次启动的生效值。

| 设置 | 调整内容 |
| --- | --- |
| 玄息归骸经 | 运功属性、内力上限收益与每周天收益、提气架势恢复、额外内力分配进度、内功策略生成概率、体魄神识收益、伤势自动恢复速度 |
| 照影游身步 | 运功属性、施展移速、体魄收益、单位脚力抵伤效率 |
| 两仪还形功 | 运功属性、施展御体御气及化解、体魄收益、残毁部位恢复层数 |
| 万噬血隙拳 | 运功属性、施展穿透与命中、体魄收益、血隙基础触发概率、每层血隙追击威力 |
| 四件套 | 主战斗属性加成、普通攻击威力加成、内功恢复加速、身法/护体的施展加成、血隙保底概率增幅 |

数值倍率并非最终战斗伤害倍率。单诀和套装可以共同作用，例如身法基础移速先受身法设置影响，再获得套装加成。血隙设为 50% 时，基础触发率为 10%，每层追击威力为 +75%；套装保持 100% 时，其普攻加成仍为 +100%。

等级、功法身份、正逆练关系、学习突破门槛、格数、招式需求、施展消耗、范围与时长保持原设计。血隙的完整普攻判定、2 层获取、10 层上限、必中必重创与免反震，以及两仪伤势重分配机制保留；套装仍需装备四诀。这些是机制与结构参数，未作为收益数值相乘。

整数收益四舍五入；两仪的不足一层恢复按概率处理，如 50% 时每次防御结束有 50% 概率为残毁部位减少 1 层，然后照常重分配。内功恢复使用进度累积保留小数速率；默认值保留原每 10 次/套装每 5 次的恢复节奏。内力设置改变配置收益，不追溯重写人物已经获得的内力。

## 原生链路与依据

- 当前官方 SliderSetting 的字段为 SettingType、Key、DisplayName、Description、GroupName、DefaultValue、MinValue、MaxValue、StepSize；保存为整数。
- 前端先 ApplySettings，再由 PluginHelper 设置 ModIdStr 并调用 Initialize；后端先填充 ModInfoDict，再调用插件 Initialize。因此可在两端初始化时取得同一组设置。
- 前端 ModManager.GetSetting 与后端 DomainManager.Mod.GetSetting 分别读取原生 SerializableModData；缺项/错误类型回退 100%，越界整数夹至 10～300。未新增手写 Lua 解析器。
- 官方伤势恢复消费者取速度列表最大值，并按整数速度推进伤势恢复进度。高倍率通过本 MOD 自己的速度槽提供更多进度；仍与其他恢复效果按原生最大值规则交互。
- 需要重启是为了让配置、人物缓存、战斗效果及提示同时更新，不在战斗中局部热改。安装时保留现有 Settings.Lua，旧空文件由原生默认项补齐。

对应官方程序集身份及反编译材料见 `maintenance/20260929-strength/input-identities.json` 与 `official/`。源代码、官方消费者、实际编译 DLL 和隔离执行输出分别保留，未用源码常量列表替代产物检查。
